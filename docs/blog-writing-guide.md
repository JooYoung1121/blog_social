# 블로그 글쓰기 가이드 — "지나의 휴일"

> 외부 도구(Codex, Cursor 등 모든 AI 에이전트)가 이 레포에서 글을 쓸 때 **반드시** 따라야 하는 톤·구조·SEO 규칙. 단일 소스 코드 룰은 `scripts/lib/style-rules.ts`, 입력 양식은 `docs/writing-input-guide.md`, 작성자 컨텍스트는 `docs/author-profile.md` 참고.

---

## 0. 우선순위

1. **체험단/협찬 가이드** (input 폴더의 `client-guide.md`) — 다른 모든 룰보다 우선. 가이드의 필수 키워드/멘션/해시태그/링크는 무조건 반영.
2. **이 문서의 톤·구조·금지 규칙**.
3. **SEO 규칙**.

가이드와 다른 룰이 충돌하면 가이드가 이긴다. 단, 가이드에 명시 안 된 부분은 이 문서를 따른다.

## 1. 인사말 / 마무리 (브랜딩 일관성)

- 인사말: `안녕하세요! 지나의 휴일 지나입니다 :)`
- 마무리: `오늘 포스팅은 여기서 마무리! 궁금한 점은 댓글로 남겨주세요 😊 그럼 안녕! 👋`

모든 글의 첫 문단·끝 문단에 적용.

## 2. 톤앤매너 — "찐 엄마 톡" 스타일

### 말투 끝맺음
`~거든요.` `~더라구요!` `~하더라고요.` `~있잖아요?` `~하쥬?`

### 강조 패턴
`진짜` `완전` `딱` `너무` `정말` `확실히` `바아아아로~`

### 축약/신조어
`ㄱㄱㄱ` `찐` `맴찢` `가오리 웃음` `초보 맘` `뽕 뽑다`

### 감정 표현
- "마음이 너무 찢어지더라고요 😭"
- "정말 답이 없더라고요"
- "세상 부러울 게 없는데"

### 독자에게 말 걸기
`~아시나요?` `~하셨나요?` `~해보세요!` `~추천드려요!`

### 이모지/기호
- 😭 😂 🥹 ㅋㅋㅋ ㅠㅠ 👍 ❤️ 적재적소에 자연스럽게.
- "ㅋㅋㅋㅋ", "ㅎㅎㅎ", "ㅠㅠ"를 자연스럽게 섞어서.
- **과도한 이모지 도배 금지.**

## 3. AI 글 vs 실제 지나님 글 — 교정 표

| AI가 쓰면 나오는 패턴 (금지) | 지나님 실제 패턴 (이렇게 써야 함) |
|---|---|
| "고민되시는 분들 많으시죠?" 같은 일반적 질문 도입 | "저희 봄이가 정말 너무너무 안 먹는 거예요 😭" 같은 내 아기 구체적 에피소드 |
| `## 실제 사용 후기` 같은 밋밋한 소제목 | "제가 왜 이걸 샀냐고요? (고민의 시작)" 같은 서술형/감정형 소제목 |
| 3~4줄 한 덩어리 문단 | 1~2줄 → 빈 줄 → 1~2줄 (극단적으로 짧게 끊기) |
| "~에 도움이 됩니다" 같은 설명체 | "~하더라구요!", "~거든요.", "~있잖아요?" 구어체 |
| 감정 표현 절제 | "마음이 찢어지더라고요 😭", "제발제발 ㅠㅠㅠ" 감정 적극 표현 |
| 바로 제품 설명 시작 | 구체적 구매 계기 에피소드 먼저 ("산후도우미 이모님이 추천해주셔서") |
| 텍스트 길게 쓰고 사진 묶음 | 소제목 → 사진 1~2장 → 짧은 텍스트 → 소제목 → 사진 1~2장 패턴 |
| "다양한 감각 자극을 제공합니다" 같은 교과서 표현 | "아기가 하나씩 탐색하면서 노는 모습이 진짜 귀여워요" |

> 도입부, 소제목, 문단 길이가 가장 차이가 큰 부분.

## 4. 소제목 스타일

네이버 에디터에서는 인용 블록(`> ...`) 또는 H2 사용. 실제 지나님 패턴:

- **서술형**: "분유를 갈아타게 된 이유는 '변비&녹변' 때문 ㅠㅠ"
- **질문형**: "제가 왜 이걸 샀냐고요? (고민의 시작)"
- **꿀팁형**: "사용 추천 꿀팁!! :: 헤드쪽 솜을 2/3 정도 빼주세요!"
- **결과 예고형**: "가장 좋은 건 변비&녹변이 사라졌어요!"
- **행동 유도형**: "보정동 장난감도서관 아기엄마하면 필수로 신청하세요!"
- **시간 표시형**: "27일 신생아인데 써도 될까요?" 고민의 시작
- **비교 결과형**: "앱솔루트 명작 vs 아이엠마더 비교 결과!"

### 소제목에서 절대 하지 않는 것
- ❌ 단순 명사형: "성분", "디자인", "결론"
- ❌ "## 실제 사용 후기" 같은 밋밋한 제목
- ✅ 소제목 자체가 **하나의 이야기 문장**이어야 함

## 5. 글 구조 — 스토리텔링 흐름

### 리뷰 글의 황금 구조

```
1. 공감 도입 (내 고민/문제)
   → "저희 아기는 모로반사가 워낙 심해서..."

2. 계기 (누군가의 추천 / 검색 / 우연한 발견)
   → "산후도우미 이모님께서 조심스럽게 추천을 해주시더라고요"

3. 이 제품을 선택한 이유 (2~3가지)
   → "시중에 많은 제품이 있었지만 마베비를 선택한 이유는 두가지였어요!"

4. 실사용 경험 (기능별로 나눠서)
   → 사진과 함께 각 기능/특징을 하나씩 서술
   → 아기 반응, 내 감정을 생생하게

5. 꿀팁/노하우 (필수)
   → "사용 추천 꿀팁!! :: 헤드쪽 솜을 2/3 정도 빼서 사용하세요!"

6. 총평/추천 (누구에게 좋은지)
   → "죽전 사시는 아기 엄마하면 필.수.신.청 하세요!!"
```

### 정보성 글의 구조

```
1. 이걸 왜 정리하게 됐는지 (내 실수/경험)
2. Step by step 가이드 (스크린샷 기반, STEP 01 / 첫번째 / 두번째)
3. 핵심 정보 표로 정리
4. 주의점/팁
```

## 6. 사진 배치 규칙 (네이버 상위 블로거 패턴 분석 결과)

분석 출처: 2026-04-24 네이버 "아기체육관 추천 후기" 검색 상위 5개 블로그 (bebe_ahn, concoro, hida0, darara5670, bbang2ya_ho).

### 필수 규칙
1. **사진 연속 최대 2장까지.** 3장 이상 연속 금지.
2. **사진 뒤에 반드시 텍스트** (최소 1~2줄).
3. **사진만 덩그러니 두지 않음.** 반드시 전후에 설명.
4. **소제목 → 사진 → 설명 텍스트** 순서가 기본.
5. **2장 연속**은 "비교" 또는 "나란히 보여주기" 용도로만.

### 배치 예시
- `소제목 → 사진 1장 → 텍스트 10~30줄(짧은 문단)` 반복 (가장 흔한 패턴)
- `소제목 → 사진 2장 나란히 → 텍스트` (비교/대조 시)

### 제공 사진 사용 규칙
- **PNG/JPG/GIF는 전부 본문에 포함.** 한 장도 빠뜨리지 않음. (사용자가 직접 보정·선별한 것이므로)
- **MP4 등 영상은 조용히 스킵.** 사용자가 직접 주입함.
- **파일명 순서 = 본문 배치 순서.** 임의로 순서 바꾸지 않음 (시각적 흐름이 사용자 의도).

## 7. SEO 규칙 (2026 최신 기준)

### 제목
- 핵심 키워드를 변형 없이 제목 앞쪽 배치
- 25자 이내 권장
- 숫자/기간 포함 시 CTR 상승

### 본문
- **1,500~2,000자** (공백 포함)
- 메인 키워드 **5~7회** 자연 반복
- 연관 키워드 5~10개 자연스럽게 녹이기
- 소제목으로 구조화 (4~6개 권장)
- 문단은 1~2줄, 최대 3줄

### 내부 링크 & CTA
- 관련 기존 글 2~3개 본문 내 연결
- 마무리에 댓글 유도

> 홈피드 노출을 노리는 글은 SEO 키워드 최적화보다 감성/스토리가 우선. `docs/homefeed-strategy.md` 참고.

## 8. 절대 금지 — Hard Rules

- ❌ "감성 한 컷 📸", "감성샷은 필수죠" 같은 **필러 섹션 금지**. 모든 사진은 실질적 정보(설명·사용법·비교)와 함께.
- ❌ 본문에 **협찬/제공받음** 표현 금지 (frontmatter `sponsored`/`sponsorInfo` 필드는 유지하되 본문 노출 X).
- ❌ 본문에 **수량/사이즈(mm)/가격** 표기 금지. 가이드에 있어도 본문에 반영하지 않음.
- ❌ 본문에 **모유수유/직수/젖** 표현 금지. 봄이는 분유 수유 중. 단, 젖병/젖꼭지 같은 제품명은 허용. (`docs/author-profile.md` 참고)
- ❌ 뜬구름 잡는 칭찬 반복 ("디자인이 예뻐요~" 반복).
- ❌ 사진만 놓고 "예쁘지 않나요?" 식의 의미없는 캡션.
- ❌ 정보 없이 감성만 담은 문단.
- ❌ 스펙 나열식 서술.
- ❌ AI가 쓴 것처럼 깔끔한 문장. 구어체 자연스러움이 핵심.
- ❌ 억지 후킹/낚시성 제목 ("충격! 대박! 놓치면 손해!").

## 9. 산출물 규칙

1. **Markdown 포스트 생성** — `src/content/posts/YYYY/MM/<slug>.md`
2. **frontmatter `draft: false`** — 바로 발행 상태로. 수정은 발행 후 별도로 진행.
3. **네이버 복붙용 별도 산출물 생성 X** — `generate-naver.ts` 실행하지 않음. 웹 본문을 직접 참고해서 네이버에 올림.
4. **작업 완료 시 자동 git commit + push** — 사용자가 매번 요청하지 않아도 진행.

# 글쓰기 입력 가이드

새 글 시작할 때 어떤 정보를 어떻게 넣으면 AI가 "지나의 휴일" 톤 그대로 초안을 뽑아주는지 정리한 문서.

> 💡 룰의 단일 소스는 `scripts/lib/style-rules.ts` 입니다. 이 파일이 모든 톤·금지패턴·구조·인사말 룰을 들고 있고, AI 시스템 프롬프트와 lint 둘 다 여기서 읽어갑니다.

---

## 1. 글 작성 전체 흐름

```
0) 키워드 먼저 잡기 (2026 추가)
   npm run keywords -- --seed "실온이유식" --out input/2026-10-01-제품명
   ↳ keywords.txt + questions.txt + keyword-report.md 자동 생성

1) input/{날짜-슬러그}/ 폴더에 사진 + 텍스트 파일 준비 (아래 양식대로)

2) npm run new-post -- --input input/2026-10-01-제품명 --category baby-products
   ↳ 사진 Cloudinary 업로드 + 톤 보정 + 마크다운 뼈대 생성

3) Codex 비교 실험: Codex가 직접 본문 작성
   Claude 자동 초안: npm run generate-draft 사용
   ↳ questions.txt 가 있으면 그 질문들이 소제목으로 고정된다
   ↳ data/performance.csv 가 있으면 성과 상위 글 소제목이 예시로 주입된다

4) 본문 검토 + 수정 (지나님만 아는 디테일 보강 — 여기가 진짜 차별화)

5) npm run lint:posts → 룰 위반 체크

6) git commit & push → Vercel 자동 배포

7) /naver/<slug> 에서 블록 복붙 → 네이버 발행

8) (월 1회) 크리에이터 어드바이저 → data/performance.csv → npm run perf-report
```

## 2. input 폴더 표준 양식

```
input/2026-04-27-하베브릭스-아기체육관/
├── photos/                  # 사진 원본 (HEIC/JPG/PNG/GIF, MP4 자동 스킵)
│   ├── IMG_1001.HEIC
│   ├── IMG_1002.HEIC
│   └── ...                  # 파일명 순서 = 본문 배치 순서
├── topic.txt                # 글 제목 한 줄
├── purchase.txt             # 구매 형태 (필수)
├── keywords.txt             # 메인 + 서브 키워드
├── notes.txt                # 자유 메모 (사용 경험, 봄이 반응, 꿀팁)
├── questions.txt            # 소제목으로 쓸 질문 4~6개 (npm run keywords 자동 생성)
├── photo-notes.txt          # 사진별 한 줄 메모 (선택, 캡션 정확도 ↑)
├── product-url.txt          # 제품/서비스 링크 (선택)
├── sponsor.txt              # 협찬일 때만: 브랜드명/조건 (선택)
└── client-guide.md          # 체험단 가이드일 때만: 가이드 원문 (선택)
```

각 파일은 **있으면 자동 인식**, 없어도 무시됩니다.

## 3. 각 파일 작성 가이드

### `topic.txt` — 글의 핵심 한 줄

**좋은 예:**
```
하베브릭스 아기체육관 100일 실사용 후기
```

**나쁜 예:**
```
하베브릭스 (← 너무 짧음, AI가 글 방향 못 잡음)
하베브릭스 아기체육관 후기 어쩌고 저쩌고 막 쓰면서 다양한... (← 너무 김)
```

> 25자 이내, 핵심 키워드 + 글의 각도(후기/비교/정보 등)를 명시.

---

### `purchase.txt` — 구매 형태 (가장 중요)

다음 4개 중 **정확히 하나**를 적습니다:

| 값 | 설명 | 가격 표기 | 협찬 표현 본문 | 가이드 우선 |
|---|---|---|---|---|
| `self-purchased` | 직접 구매 | ❌ | ❌ | — |
| `sponsored` | 원고료+제품 협찬 | ❌ | ❌ | ✅ |
| `gifted` | 무상 제공만 (가이드 없음) | ❌ | ❌ | — |
| `service-experience` | 음식점·시설 등 체험단 | ❌ | ❌ | ✅ |

```
self-purchased
```

> 직구매도 구매 경로와 사용감은 자유롭게 쓰되, 본문에 금액은 쓰지 않습니다. 협찬·체험단이면 가이드 우선 + 본문에 협찬 언급 절대 금지.

---

### `keywords.txt` — SEO 키워드

첫 줄은 **메인 키워드 1개**, 두 번째 줄부터는 **서브 키워드 2~5개**:

```
하베브릭스 아기체육관
하베브릭스
바람개비 아기체육관
신생아 장난감
4개월 아기 장난감
감각 발달 장난감
```

**규칙:**
- 메인 키워드는 본문에 **5~7회** 자연 반복 (lint가 검사)
- 서브 키워드는 각각 1~2회씩
- 검색용 글은 소제목 4~6개 중 최소 2개에 메인 키워드/서브 키워드/브랜드명/제품명을 자연스럽게 포함
- 소제목은 키워드만 나열하지 말고 "검색자가 궁금해할 상황 + 답" 형태로 작성
- 키워드 잡는 법 (2026 갱신):
  - **`npm run keywords -- --seed "<키워드>"` 가 1순위.**
    네이버 검색광고 API로 연관키워드 + 월간검색수를 받고, 오픈 API로 블로그 문서수를 세서
    **기회점수(검색량 ÷ 문서수)** 순으로 정렬해준다. `--out` 을 주면 keywords.txt 까지 만들어준다.
  - ⚠️ **연관검색어 서비스는 2026-04-30 종료됐다.** 검색창 연관검색어는 더 이상 없다.
  - 보조: 네이버 검색창 자동완성, AI 탭에서 같은 질문 던졌을 때 나오는 후속 질문
  - 육아용품처럼 문서수가 많은 영역은 기회점수가 낮게 나온다.
    이때는 **조합 2단계 이상**(제품군 + 상황 + 월령)으로 내려가야 한다.
    예: `이유식` → `중기이유식` → `중기이유식 실온보관`

### `questions.txt` — 소제목으로 쓸 질문 (2026 신규)

`npm run keywords -- --out <dir>` 가 자동 생성한다. 직접 써도 된다.

```
# 소제목으로 쓸 질문 (각 질문 아래 첫 문단 = 그 질문만의 완결 답변)
실온이유식은 정말 냉장고에 안 넣어도 되나요?
중기이유식은 몇 개월부터 먹이나요?
외출할 때 이유식 어떻게 챙기나요?
데워서 줘야 하나요 그냥 줘도 되나요?
냉동이유식이랑 뭐가 다른가요?
개봉하고 남으면 어떻게 보관하나요?
```

**왜 중요한가:** 2026 하반기 네이버의 실질 KPI는 검색 순위가 아니라 AI 브리핑 인용수다.
AI 브리핑은 "질문 → 그 문단만 읽어도 답이 되는 답변" 단위로 글을 잘라 인용한다.
소제목이 검색자의 실제 질문과 일치할수록 인용 확률이 올라간다.

`#` 으로 시작하는 줄은 주석으로 무시된다.

---

### `photo-notes.txt` — 사진별 한 줄 메모 (선택)

지금은 Claude가 사진만 보고 캡션을 **추정**한다. 한 줄씩만 남겨도 정확도가 크게 오른다.

```
01 택배 뜯자마자 찍은 거. 박스 안에 유리병 4종
02 상부장에 그냥 세워둔 모습 — 냉장고 안 쓴다는 걸 보여주려고
05 봄이가 처음 먹어본 날. 표정이 애매했음
```

### `notes.txt` — 자유 메모 (가장 풍부할수록 좋음)

AI가 진짜 "지나님 톤"으로 쓰려면 **본인의 경험 디테일**이 필요합니다. 키워드 나열 말고 **이야기로** 적으세요.

> 💡 **2026 권장: 아래 항목 형식으로 적어주세요.**
> 자유 나열이면 AI가 글의 구조를 *추측*해야 하고, 그 추측이 "AI 티"의 가장 큰 원인입니다.
> 항목으로 주면 그대로 소제목 4~6개 + FAQ 3~5개 + TL;DR로 변환됩니다.

```
[언제부터/얼마나]
8월 20일부터 약 5주. 하루 2회.

[사기 전 고민]
냉동실이 꽉 차서 자리가 없었음. 시판 이유식은 다 냉동이라 포기하려던 참.

[계기]
조리원 동기가 실온 보관 되는 게 있다고 알려줌.

[봄이 반응 — 전]
기존 냉동 이유식은 데우는 데 오래 걸려서 그 사이에 울었음.

[봄이 반응 — 후]
바로 데워지니까 안 울고 먹음. 양도 더 먹음.

[실패/아쉬운 점]      ← 가장 중요
유리병이라 외출할 때 무거움. 깨질까 봐 신경 쓰임.

[꿀팁]
뚜껑 열기 전에 흔들면 안 됨. 분리된 채로 데우는 게 나음.

[비교 대상]
기존에 쓰던 ○○ 냉동 이유식과 비교하면 데우는 시간이 확실히 짧음.

[재구매 의사]
외출용으론 계속 살 듯. 집에서만 먹일 거면 굳이.
```

**`[실패/아쉬운 점]`이 왜 가장 중요한가:**
AI가 만들 수 없는 정보는 "직접 겪은 것"뿐입니다. 장점만 나열된 글은 AI 생성물과 구분되지 않고,
2026 네이버는 AI 스팸을 실시간 필터링합니다. 아쉬운 점 한 줄이 글 전체의 신뢰도를 만듭니다.
(협찬 글이어도 마찬가지입니다 — 가이드가 금지하지 않는 한 솔직한 단점은 넣습니다.)

---

**자유 형식으로 쓸 때의 좋은 예:**
```
- 아는 언니가 추천해줬는데 6개월 동안 쓸 거라 망설였음
- 봄이가 처음엔 누워서 발로 차다가 4개월부터 손으로 잡고 놀기 시작
- 바람개비가 시각 자극에 좋다더라 — 봄이 진짜 한참 쳐다봄
- 단점: 매트가 살짝 미끄러움 — 러그 위에 깔아서 해결
- 꿀팁: 모빌은 밤에 떼고 자면 더 잘잠
- 친구 아이도 놀러왔을 때 너무 좋아함
```

**나쁜 예:**
```
좋은 제품임
가격 대비 만족
추천함
```
→ AI가 살을 못 붙이고 일반적인 글이 나옴.

> 디테일이 많을수록 AI가 "찐 후기" 톤을 살릴 수 있어요. 봄이 반응, 단점, 우연한 발견, 다른 엄마들 반응 등 구체적으로.

## 4. purchaseType 별 작성 팁

### 🛒 `self-purchased` (직접 구매)
- "당근에서 샀어요", "스마트스토어에서 직접 주문" 같은 표현 자연스럽게
- **금액 표기 X** — "가성비가 좋았어요"처럼 느낌만 쓰고 구체 금액은 쓰지 않음
- 단점도 솔직하게: "근데 매트가 살짝 미끄러워서..."
- 다른 제품과 비교 자유

### 🎁 `sponsored` (원고료+제품)
- 본문에 "협찬받아", "제공받아" 절대 X (frontmatter sponsorInfo로만 표시)
- 가격·수량·사이즈 본문 표기 ❌
- 단점은 **완곡하게**: "처음에는 적응이 좀 필요했지만..."
- **체험단 가이드의 키워드/멘션이 SEO 룰보다 우선**

### 🎀 `gifted` (무상 제공, 가이드 없음)
- 협찬 표현 본문 X (sponsored와 동일)
- 가이드가 없으니 **솔직 후기 OK** (단점도 표현 가능)
- 가격 정보는 X

### 🍽 `service-experience` (음식점/시설 체험단)
- "방문해봤어요!" 톤
- 위치·분위기·메뉴(맛 위주) → 가격은 본문에 X
- 가이드 키워드 우선

## 5. 키워드 잡는 법 (네이버 SEO)

### 메인 키워드 1개
- 검색량이 적당히 있는 키워드 (월 1만~10만)
- 너무 큰 키워드(예: "아기")는 경쟁이 너무 강함
- 너무 작은 키워드(월 100 이하)는 의미 없음

### 서브 키워드 2~5개
- 메인 키워드의 **변형/세분화**
- 롱테일: "아기체육관" → "4개월 아기체육관 추천"
- 연관어: "아기체육관" + "신생아 장난감", "감각 발달"

### 도구
- **자동완성**: 네이버 검색창에 키워드 치면 인기 검색어 자동완성
- **연관 검색어**: 검색 결과 하단의 연관 검색어
- **키워드마스터** (`whereispost.com/keyword`): 검색량/경쟁도 확인

## 6. 글 쓰고 난 뒤 체크리스트

```bash
# 1) lint 검사
npm run lint:posts src/content/posts/2026/04/2026-04-27-제품명.md

# 2) 로컬 미리보기
npm run dev → http://localhost:4321/posts/2026-04-27-제품명

# 3) 빌드 확인 (배포 전 마지막 체크)
npm run build

# 4) 커밋 & 푸시 → Vercel 자동 배포
git add . && git commit -m "feat: 새 글 — 제품명" && git push
```

### lint가 잡아내는 항목
- ✅ 인사말/마무리 정형 문구 사용 여부
- ✅ purchaseType별 금지 패턴 (협찬/가격/모유수유/감성컷 등)
- ✅ 본문 글자수 1500~2000자
- ✅ 메인 키워드 5~7회 빈도
- ✅ 메인 키워드가 소제목에 최소 1회 포함됐는지 확인
- ✅ 사진 3장 이상 연속 금지
- ✅ 명사형 소제목 검출

## 7. Codex 비교 실험 흐름

Codex 결과물과 Claude 결과물을 비교할 때는 같은 input 폴더를 사용하되, 생성 방식은 분리합니다.

- Codex: `docs/codex-workflow.md`를 따라 사진 업로드 후 Markdown 본문을 직접 작성
- Claude: 아래 `npm run generate-draft` 명령으로 Claude API 자동 초안 생성

Codex 비교용 작업에서는 `npm run generate-draft`를 본문 생성에 사용하지 않습니다. 이 명령은 내부에서 Claude 모델을 호출하기 때문입니다.

자세한 Codex runbook은 [`docs/codex-workflow.md`](docs/codex-workflow.md)를 참고하세요.

## 8. Claude 자동 글 생성

```bash
npm run generate-draft -- --input input/2026-04-27-제품명 --category baby-products
```

이 한 줄로:

1. 입력 폴더의 `topic.txt`, `purchase.txt`, `keywords.txt`, `notes.txt`, (있으면) `client-guide.md` 읽기
2. 사진 Cloudinary 업로드 + 톤 보정
3. `buildSystemPrompt()` 으로 룰 100% 반영된 시스템 프롬프트 생성 → ephemeral 캐시 (90% 비용 절감)
4. **Claude Opus 4.7 멀티모달 호출** — 사진을 Claude가 직접 보고 정확한 캡션 작성
5. 생성된 마크다운에 자동 lint 실행 (룰 위반 검사)
6. `src/content/posts/YYYY/MM/{slug}.md` 에 저장

### 옵션

```bash
--intent review       # review (기본) | compare | info | location | diary
--target search       # search (기본) | homefeed | both
--model claude-...    # 기본: claude-opus-4-7. 비용 절감 시 claude-sonnet-4-6
--no-tone             # 사진 톤 보정 끄기
```

### 필요한 환경변수

`.env` 에 추가:
```
ANTHROPIC_API_KEY=sk-ant-...
```
키 발급: https://console.anthropic.com/settings/keys

### 비용 가늠

- 시스템 프롬프트(약 4000자) → ephemeral 캐시 → 두 번째 호출부터 90% 할인
- 사진 10장 + 메모 500자 + 응답 2000자 ≈ Opus 4.7 기준 첫 호출 ~$0.20, 같은 날 재호출 ~$0.05
- Sonnet 4.6 사용 시 약 1/2 가격

> 사용자는 **`notes.txt`에 본인 경험 디테일을 풍부히 적기만 하면** 됩니다. 톤·구조·금지패턴은 코드(`style-rules.ts`)가 보장.

## 9. 자주 묻는 질문

**Q. 사진 순서를 바꾸고 싶어요**
→ `photos/` 폴더에서 파일명 prefix를 `01_`, `02_`처럼 붙이면 그 순서대로 배치됩니다.

**Q. 사진을 일부만 쓰고 싶어요**
→ 룰상 **제공된 사진은 영상(MP4) 빼고 전부** 사용하게 되어있어요. 빼고 싶은 사진은 `photos/` 폴더에서 제외하고 시작하세요.

**Q. 글을 나중에 수정했어요. 신선도 신호 어떻게 줘요?**
→ frontmatter에 `updated: 2026-05-01` 추가. JSON-LD `dateModified`와 OG `article:modified_time`이 자동 갱신됩니다.

**Q. 같은 제품 글을 검색용 + 홈피드용 두 개로 쓰면?**
→ frontmatter `target: search` vs `target: homefeed` 로 분리. 톤·제목·구조가 자동으로 다르게 잡힙니다.
